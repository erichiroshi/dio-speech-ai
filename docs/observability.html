Métricas — implementadas (v2.1.0)

Expostas em /actuator/prometheus · Scraping pelo Prometheus a cada 10s

MétricaTipoTagsDescrição
transcription.requests.total Counter status=success|error Total de transcrições realizadas
transcription.whisper.duration Timer — Latência das chamadas ao Whisper (p50/p95/p99)
transcription.file.size.bytes Distribution — Distribuição dos tamanhos de arquivo enviados
http.server.requests Timer uri, method, status Métricas HTTP automáticas (Spring Boot)

Endpoints Actuator

EndpointDescrição

Queries Prometheus úteis

# Taxa de sucesso por minuto
rate(transcription_requests_total{status="success"}[1m])

# Taxa de erros por minuto
rate(transcription_requests_total{status="error"}[1m])

# p99 de latência do Whisper
histogram_quantile(0.99,
  rate(transcription_whisper_duration_seconds_bucket[5m]))

# Tamanho médio dos arquivos (bytes)
transcription_file_size_bytes_sum / transcription_file_size_bytes_count

# Throughput HTTP geral (req/s)
rate(http_server_requests_seconds_count[1m])

Logs estruturados

⏳ v2.2.0

Atualmente os logs são texto simples via Logback padrão. Na v2.2.0 serão migrados para JSON com logstash-logback-encoder, enriquecidos via MDC com requestId, fileName e fileSizeBytes.

Tracing distribuído

⏳ v2.7.0

Tracing com OpenTelemetry + Zipkin será implementado na v2.7.0. O trace_id aparecerá automaticamente nos logs JSON via MDC, conectando métricas, logs e traces num mesmo fluxo rastreável.

## Decisões e trade-offs

### SimpleMailMessage vs MimeMessage

`SimpleMailMessage` (texto plano) foi escolhido por simplicidade.
Para e-mail HTML com template Thymeleaf, seria necessário `JavaMailSender.createMimeMessage()`
e `MimeMessageHelper`. O texto plano atende o objetivo de demonstrar o padrão
sem adicionar complexidade de template engine.

**Evolução futura:** `MimeMessageHelper` + template Thymeleaf em `resources/templates/`.

### GreenMail em vez de conta SMTP real

GreenMail é um servidor SMTP embarcado (sem processo externo, sem Docker, sem conta).
Sobe na porta aleatória via `@DynamicPropertySource` — sem conflito de porta entre
execuções paralelas. O teste verifica o conteúdo real do e-mail (subject, destinatário,
corpo) via `greenMail.getReceivedMessages()`.

```java
@DynamicPropertySource
static void mailProperties(DynamicPropertyRegistry registry) {
    greenMail = new GreenMail(new ServerSetup(0, "127.0.0.1", "smtp"));
    greenMail.start();
    registry.add("spring.mail.port", () -> greenMail.getSmtp().getPort());
}
```

**Por que `RabbitAutoConfiguration` é excluída neste teste?**
O `@SpringBootTest` sobe o contexto completo, incluindo o `SimpleMessageListenerContainer`
que tenta conectar ao RabbitMQ. Como o teste não precisa de RabbitMQ e não usa
Testcontainers para isso, excluir a autoconfiguração elimina o warning de conexão.

### EmailProperties via @ConfigurationProperties

Em vez de `@Value("${notification.email.from}")` direto no adapter, usamos um record
`@ConfigurationProperties`. Isso permite validação de presença e IDE autocomplete
no `application.yml`. O record é excluído do Jacoco (sem lógica testável).

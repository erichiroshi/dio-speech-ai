## Decisões e trade-offs

### Validação no use case, não no controller

A validação de `contentType` ficou no `TranscribeAudioUseCase.validate()`,
não no `TranscriptionController`. Isso garante que qualquer adapter de entrada
— HTTP ou RabbitMQ (Fase 8) — receba a mesma validação automaticamente.

Se a validação estivesse só no controller, um pedido chegando via fila poderia
passar um tipo inválido sem ser rejeitado.

```java
private static final Set<String> ALLOWED_TYPES = Set.of(
    "audio/wav", "audio/mpeg", "audio/wave", "audio/x-wav");

private void validate(TranscribeCommand command) {
    if (command == null) throw new TranscriptionException("Arquivo ausente");
    if (contentType == null) throw new TranscriptionException("Content-Type não informado");
    if (!ALLOWED_TYPES.contains(contentType.toLowerCase()))
        throw new TranscriptionException("Tipo inválido: " + contentType);
}
```

### Por que SHA-256 no use case e não no adapter de cache?

O hash é uma decisão de negócio: dois arquivos com conteúdo idêntico
são equivalentes para fins de cache. O adapter de cache recebe o hash
pronto — não precisa saber como foi calculado. Se a estratégia de hash
mudar, muda em um lugar só.

### Teste unitário puro — o maior ganho da Fase 7

```java
@ExtendWith(MockitoExtension.class)
class TranscribeAudioUseCaseTest {
    @Mock SpeechToTextPort speechPort;
    @Mock TranscriptionCachePort cachePort;
    @Mock TranscriptionEventPort eventPort;
    @Mock TranscriptionMetrics metrics;
    @InjectMocks TranscribeAudioUseCase useCase;
}
```

- Zero Spring context
- Zero Docker / Testcontainers
- Executa em ~20ms
- Testa a lógica de negócio isolada

Antes, para testar o fluxo de cache era necessário o `TranscriptionIntegrationTest`
com Redis real (~10s de startup). Agora o mesmo cenário testa em ~20ms.

### `TranscriptionService` ainda ativo nesta versão

O use case existe mas o controller ainda aponta para `TranscriptionService`.
Isso é intencional: a migração é incremental, o comportamento HTTP não muda.
O controller é reconectado ao use case na v7.5.0.

## Decisões e trade-offs

### WhisperAdapter: `ByteArrayResource` em vez de `byte[]` diretamente

O WebClient com `MultipartBodyBuilder` requer um objeto que implemente
`Resource` para enviar como parte multipart com filename. `byte[]` puro
não funciona — o Speaches precisa de um filename para processar o arquivo.

A solução foi sobrescrever `getFilename()` em `ByteArrayResource`:

```java
ByteArrayResource resource = new ByteArrayResource(audioBytes) {
    @Override
    public String getFilename() {
        return "audio.wav";
    }
};
body.part("file", resource);
```

**Trade-off:** o nome `"audio.wav"` é hardcoded no adapter. Para suporte
a MP3 no futuro, o `WhisperAdapter` poderia receber o filename como parâmetro
adicional ou derivar a extensão do `contentType`.

### WhisperAdapter vs SpeechToTextClient

| | SpeechToTextClient (antes) | WhisperAdapter (depois) |
|---|---|---|
| Interface | Nenhuma — classe concreta | Implements `SpeechToTextPort` |
| Parâmetro | `MultipartFile` | `byte[]` |
| DTO | `WhisperResponse` (público) | Record privado interno |
| Localização | `transcription/service/` | `transcription/infrastructure/speechtotext/whisper/` |

### RedisTranscriptionCacheAdapter: `Optional` em vez de nullable

O `CacheService` retornava `null` em caso de miss — o chamador precisava
verificar `if (cached != null)`. O adapter retorna `Optional<TranscriptionResult>`:
o compilador força o tratamento do caso vazio.

### RedisConfig: tipo alterado para `TranscriptionResult`

O cache agora armazena `TranscriptionResult` (domínio application) em vez
de `TranscriptionResponse` (DTO HTTP). O adapter de cache não conhece
representações HTTP.

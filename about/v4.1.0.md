## Por que SpringDoc e não Springfox?

O Springfox era o padrão anterior para Swagger em projetos Spring, mas foi abandonado e não suporta Spring Boot 3+. O SpringDoc é a alternativa ativa e mantida, compatível com Spring Boot 3.x e 4.x, e gera especificações OpenAPI 3.1 (Springfox gerava OpenAPI 2/Swagger 2).

A dependência `springdoc-openapi-starter-webmvc-ui` inclui tudo: geração da spec JSON, servidor de UI (Swagger UI embutido via WebJars), e a integração com Spring MVC.

---

## O que o SpringDoc gera automaticamente

Sem nenhuma anotação, o SpringDoc inspeciona os controllers por reflexão e gera:

- Todos os endpoints com seus métodos HTTP e paths
- Parâmetros (`@RequestParam`, `@PathVariable`, `@RequestPart`)
- Schemas dos DTOs (records são suportados)
- Respostas padrão (200)
- Grupos de operações por controller

As anotações (`@Operation`, `@ApiResponse`, `@Schema`) são opcionais — servem para enriquecer a documentação com descrições, exemplos e status de erro.

---

## OpenApiConfig — decisões

**Segurança global**: a configuração define `bearerAuth` como requisito global via `.addSecurityItem()`. Isso significa que todas as operações aparecem com o cadeado no Swagger UI. Operações públicas (`/auth/token`) sobrescrevem esse comportamento com `@SecurityRequirements` vazio.

**Por que não usar `@SecurityRequirement` por operação?** Para o caso deste projeto, onde quase todos os endpoints são protegidos, é mais seguro definir o requisito globalmente e marcar explicitamente as exceções. O risco inverso (esquecer de marcar um endpoint como protegido) é pior.

**Servidores**: dois servidores definidos (dev e prod) permitem que o Swagger UI aponte para o ambiente correto ao usar "Try it out".

## Anotações nos controllers

### @Tag

Agrupa operações no Swagger UI. Sem `@Tag`, cada controller aparece com seu nome Java. Com `@Tag(name = "Transcrição")`, os endpoints são agrupados sob "Transcrição" com a descrição informada.

### @Operation

Documenta uma operação específica: summary (aparece na lista), description (aparece expandida), e security (sobrescreve o requisito global).

### @ApiResponses / @ApiResponse

Documenta os status HTTP possíveis com exemplos de body. Os exemplos aparecem no Swagger UI e tornam a documentação muito mais útil do que apenas listar status codes.

### @SecurityRequirements (vazio)

Aplicado em `AuthController.token()` para indicar que este endpoint não requer autenticação. Sem isso, o Swagger UI mostraria o cadeado fechado em `/auth/token`, confundindo quem tenta usá-lo para obter um token.

### @Schema nos records

Adiciona descrição e exemplo a cada campo do `TranscriptionResponse`. Aparece no Swagger UI como tooltip e no schema JSON gerado.

## SecurityConfig — rotas liberadas

O Spring Security intercepta todas as requisições antes do SpringDoc. Sem liberar as rotas, o Swagger UI retornaria 401 ao tentar carregar a spec.

Rotas adicionadas ao `permitAll()`:

```java
.requestMatchers(HttpMethod.GET, "/v3/api-docs/**").permitAll()   // spec JSON
.requestMatchers(HttpMethod.GET, "/swagger-ui/**").permitAll()    // assets da UI
.requestMatchers(HttpMethod.GET, "/swagger-ui.html").permitAll()  // redirect
```

## Como usar o Swagger UI para transcrever

1. Acesse `http://localhost:8080/swagger-ui.html`
2. Expanda **Autenticação → POST /auth/token**
3. Clique em **Try it out**, insira `{"username":"user","password":"any"}` e execute
4. Copie o valor do campo `token` na resposta
5. Clique em **Authorize 🔒** (botão no topo direito da página)
6. Cole o token no campo `bearerAuth` e confirme
7. Expanda **Transcrição → POST /api/transcriptions**
8. Clique em **Try it out**, selecione um arquivo `.wav` e execute
9. Observe a resposta — na segunda execução com o mesmo arquivo, `"cached": true`

## Trade-offs

| Decisão | Alternativa | Por que esta |
|---|---|---|
| SpringDoc | Springfox | Springfox abandonado; não suporta Spring Boot 3+ |
| Spec gerada em runtime | Spec manual (arquivo YAML no repo) | Spec sempre sincronizada com o código; zero drift |
| Requisito JWT global + exceções explícitas | Requisito por operação | Mais seguro — força o dev a marcar explicitamente endpoints públicos |
| `springdoc.paths-to-exclude: /actuator/**` | Incluir endpoints do Actuator | Actuator tem sua própria documentação; poluiria a spec da API |
| `try-it-out-enabled: true` | Desabilitado por padrão | Facilita testes rápidos sem sair do browser |
